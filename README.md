# Role-Chaining Pipeline

## Описание

Проект реализует **Role-Chaining Pipeline** — последовательную смену ролей одной LLM по шагам 1→9 для решения сложных задач. Каждая роль генерирует артефакт, который валидируется и передаётся следующей роли.

## Структура проекта

```
├── config/
│   ├── pipeline.yaml          # Конфигурация шагов 1-9
│   ├── models.yaml            # Карта ролей → моделей
│   └── schemas/               # JSON Schema для валидации артефактов
├── prompts/
│   ├── _base.md               # Глобальные правила
│   ├── snippets/              # Переиспользуемые фрагменты промптов
│   └── 01_orchestrator.md ... 09_security.md  # Промпты для каждого шага
├── src/
│   ├── __init__.py
│   ├── llm_client.py          # Клиент для вызова LLM
│   ├── artifact_store.py      # Хранилище артефактов
│   ├── validators.py          # Валидация по JSON Schema
│   ├── utils.py               # Утилиты
│   └── pipeline_runner.py     # Основной движок пайплайна
├── scripts/
│   ├── run_pipeline.py        # CLI точка входа
│   └── replay_run.py          # Перезапуск конкретного шага
├── artifacts/                 # Сохранённые артефакты по запускам
├── .env                       # Переменные окружения (не коммитить)
├── .env.example               # Пример переменных окружения
├── requirements.txt           # Зависимости
└── README.md                  # Этот файл
```

## Логика пайплайна

### Шаги (1-9):

1. **Orchestrator** — Декомпозиция цели на подзадачи
2. **Researcher** — Сбор контекста и требований
3. **Architect** — Проектирование архитектуры (ARD)
4. **TDD Engineer** — Написание тестов перед кодом
5. **Builder** — Реализация кода
6. **Prompt Engineer** — Создание промпт-пакета
7. **Tester** — Запуск тестов и отчёт
8. **Critic** — Код-ревью и оценка качества
9. **Security Auditor** — Аудит безопасности

### Feedback Loops:

- **Тестировщик → Билдер**: максимум 2 повтора при провале тестов
- **Критик → Биллер/Промпт-инженер**: возврат на доработку при низком качестве

### Fail-Fast:

- Валидация артефактов по JSON Schema перед переходом на следующий шаг
- При ошибке — попытка исправления или остановка с сохранением состояния

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
# Отредактируйте .env, указав ваш API ключ и модель
```

## Запуск

```bash
python scripts/run_pipeline.py --goal "Ваша цель здесь"
```

### Опции:

- `--goal`: Цель для выполнения (обязательно)
- `--config`: Путь к конфигурационному файлу (по умолчанию `config/pipeline.yaml`)
- `--resume`: ID запуска для продолжения (`run_id`)

## Перезапуск шага

```bash
python scripts/replay_run.py --run-id <run_id> --step <step_number>
```

## Логи и артефакты

- Логи пайплайна: `pipeline.log`
- Метаданные запуска: `artifacts/run_<timestamp>/meta.json`
- Артефакты: `artifacts/run_<timestamp>/<step>_<role>.json`
